# The Tags dialog stays below the toolbar and can fade

- Situation: a bottom sheet or dialog sits under a fixed toolbar in z-order, and on a phone a long list grew it to the top of the screen, where the toolbar covered its title and Close. Separately, a dialog that tunes the graph behind it hid the very graph the reader was watching.
- Proposed: leave the sheets uncapped (`max-height: 100% - 2rem`), with the backdrop as the only way out once the header was covered; no way to see through the Tags dialog.
- Chosen:
  1. **Cap and scroll, with a pinned header.** Each panel's height stops at the toolbar's measured clearance, and the panel scrolls inside itself. The toolbar publishes `--graph-toolbar-clearance` on `<html>` from its own box (its bottom edge plus the same gap it keeps above itself, followed by a ResizeObserver as it wraps), so nothing guesses the toolbar's height. The header (title, Close, the new opacity slider) is `position: sticky` at the panel's top.
  2. **Applies to the Tags dialog and the node edit sheet.** The edit sheet gets the same cap; its header (title, Close) is pinned at the top and its Pin/Delete/Cancel/Save row is pinned at the bottom of the details tab.
  3. **An opacity slider in the Tags header, beside Close.** Labelled "Dialog opacity", range 0–100% in 5% steps, `aria-valuetext` and a visible readout as a percentage, default 100%.
  4. **Everything but the slider fades; the backdrop fades twice as fast; 0 is allowed.** The panel and Close take the chosen opacity `o`; the backdrop takes `max(0, 2·o − 1)`, so it is gone by the time the panel is at half. The slider stays fully opaque on its own white chip at every value, so a dialog faded to nothing still shows the way back. The slider sits outside the faded panel element, over its pinned header, because CSS opacity on an ancestor cannot be undone by a descendant. While a length or spacing slider is hovered or keyboard-focused, **that slider's own control** (track and readout) dips to 50% over about 200 ms and returns on leave or blur; the dialog's opacity stays at the chosen value. Under reduced motion the dip is instant.
  5. **A per-browser viewing preference.** The chosen opacity is kept in `localStorage` under `mind-map:dialog-opacity` (the app's storage namespace, beside the settings seed), read and written defensively, and never in the graph or the file. At 100% the key is removed.
  6. **The dialog still takes pointer events at every opacity.** A faded or invisible panel is still a modal dialog: presses land on it, never on the graph behind; the backdrop still closes it.
- Why: owner rulings of 2026-10-12, given as directives without a quoted reason. The cap fixes the TODO bug in which the toolbar covered the Tags heading and Close on a 375px phone. The opacity lets the reader see the graph react while tuning per-tag layout from the legend. The dip was first ruled as a whole-dialog dip to `min(0.5, chosen)`; the owner corrected it the same day to dip only the slider being tuned.
- Pattern: overlay--prove-the-control-is-hittable; motion--make-reduced-motion-reach-the-same-end-state
- Status: ruling
