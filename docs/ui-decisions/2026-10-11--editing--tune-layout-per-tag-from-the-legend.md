# Tune the layout per tag from the legend

- Situation: letting the reader make one kind of edge longer or one kind of node roomier without opening the settings panel, which only tunes the whole graph. The tag legend already lists every node and edge tag with its colour, so it is where a per-tag knob belongs.
- Proposed: a per-tag "attraction" slider wired to spring strength; a linear slider; multiplying the factors of every tag an element carries; one undo entry per `input` event.
- Chosen: each legend row gets a slider **left of its colour input**. An edge tag's slider sets **edge length** — a rest-length multiplier on both ends of the edge's rest-gap band — and a node tag's sets **node spacing** — a multiplier on the extra clearance hop repulsion holds open around the node. Spring strength is not exposed per tag. The slider is **logarithmic** over factors `[0.25, 4]`, with ×1 at the centre; the readout is `×` plus two significant figures, prefixed by a visible word — `length ×1.4` on edge rows, `spacing ×1.4` on node rows — and the bare factor is also the slider's `aria-valuetext`. An element with several tuned tags uses the **geometric mean** of the configured tags' factors (untuned tags are ignored), and a node pair uses the geometric mean of its two nodes' factors. A drag is **one undo entry**: `input` frames preview live and coalesce, the release commits; each arrow-key press is its own entry. The dialog and its toolbar button are retitled **"Tags"**, since it now holds more than colour.
- Why: from the plan's resolutions of rulings the owner made (no verbatim quote). The physics holds an edge anywhere inside its band and corrects only outside it, so spring strength changes how fast an edge gets to rest, not where it rests — a strength slider would be dragged and change nothing visible. A log scale makes ×2 and ×0.5 equal distances from the centre. The product of factors was rejected because two "slightly shorter" tags (0.9, 0.8) would give 0.72, shorter than either asked for; the geometric mean stays between its inputs and lets ×2 and ×0.5 cancel. The visible word was the plan agent's choice — a bare `×1.4` beside a swatch does not say what it scales — and the owner kept it. One entry per drag matches the colour scrub ruling of 2026-08-30.
- Risk, named so it is not read as a bug later: a node's spacing also lengthens its **own** edges. Hop repulsion applies to adjacent pairs too (`hopRepulsionMinHops` clamps up to 1), so a high spacing factor asks for more room from each neighbour than the edge band allows, and the push and the spring settle in between. "Space around the node" includes its neighbours. The converse also holds: below about ×0.6 an edge-length factor is contested by that same hop-1 repulsion, so the slider's lower half shortens edges by less than its number says.
- Addendum (2026-10-11, same day, owner request — "the tag's node spacing slider needs more range on the high end"): a node pair now uses the **larger** of its two nodes' factors, `max(fa, fb)`, not their geometric mean, and the range widens to **`[0.125, 8]`** (the log slider runs `-3`…`3`, step and readout unchanged: `×8.0`, `×0.13`). Why: the owner found ×4 too weak. The geometric mean halved a lone tuned node's factor in log space — ×4 beside an untuned neighbour held only ×2 clearance — and because hop repulsion only pushes, a pair already past its preferred distance never moves, so a doubled clearance often changed little on screen. `max` is still symmetric, so the push stays equal and opposite, and a node tuned to ×4 now holds ×4 against every other node; a spacing below ×1 only takes effect between two nodes that both ask for less. The per-element rule for several tags on one node or edge (geometric mean of the configured tags) is unchanged. Files saved with ×4 open unchanged; the load clamp reads the new bounds. The named risk above grows with it: at ×8 a node asks its own neighbours for far more room than the edge band allows.
