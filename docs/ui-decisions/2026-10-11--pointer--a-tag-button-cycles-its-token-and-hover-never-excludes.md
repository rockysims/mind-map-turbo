# A tag button cycles its token, and hover never previews an exclude

- Situation: the Find / Filter panel's node-tag and edge-tag buttons, which could only append a plain `#tag` / `@tag` to the query — a second click added a duplicate, and spotlighting, excluding or removing a tag meant retyping the query by hand. Hovering or keyboard-focusing a button previewed `+#tag` unconditionally.
- Proposed: keep the buttons append-only, or add a second control per tag for the other modes.
- Chosen: each button is a four-state toggle for its own token — none → `#tag` (focus) → `+#tag` (spotlight) → `-#tag` (exclude) → none — that edits only that token's range in the typed query. The button reports the _effective_ mode: if the query names the tag more than once, exclusion wins (as it does in evaluation), otherwise the last token's mode. Its label is the token as it would be typed, with `aria-pressed`, `data-mode`, a darker inset border and semibold label (not hue alone) separating none from focus, and an accessible name of `Node tag lab, <state>`. Hover and keyboard focus preview a spotlight only for a tag that is not in the query; a tag with a token previews nothing, and no preview ever excludes.
- Why: from the plan's resolutions of a design the owner decided (no verbatim quote): the order is the grammar's own escalation — show it, emphasise it, hide it, forget it — so one button reaches every mode with no second control, and the label changing on each click teaches the cycle without a hint line. Reporting the effective mode keeps the button agreeing with what the graph shows for a hand-typed `-#lab #lab`. The preview is deliberately not "what the next click would do": excluded nodes are planned to leave the layout, so previewing an exclude on hover would reflow the graph under the pointer, and previewing over a chosen token would silently override the state the user just picked.
- Pattern: none — the none/focus treatment follows a11y--never-let-colour-carry-meaning-alone; "a preview must not move what the pointer is over" has no library entry yet.
- Status: ruling
