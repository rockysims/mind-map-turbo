# Border sources are four, and each names its scale

- Situation: "Border shows" offered six options (Nothing, Size, Node weight, Edge count, Attachments, Description length), all drawn on one log curve. The owner could not tell whether "Attachments" was a count or a size, and there were more options than meanings: "Size" was the node's `sizeBytes`, the size of the thing the node stands for, which readers took for the size of its attachments.
- Proposed: keep the six and add help text; or keep one shared log curve for every source.
- Chosen: four sources plus **Nothing** (the default), each label naming its scale: **Node weight (linear)**, **Edge count (linear)**, **Attachment size (logarithmic)** — the total bytes of the node's attachments, images and files alike — and **Description length (logarithmic)**, so a reader can see which nodes have a description and roughly how long. Linear: twice the reference draws twice the border. Logarithmic: each doubling adds "Width per doubling", which only these two use. On every source a value of 0 (no edges, nothing attached, an empty description, a weight of 0) draws the thinnest border; a node with no weight draws the normal one. The Size and attachment-count sources are removed. `sizeBytes` stays as data and keeps its details line; it no longer drives the border. The help line under the select says what the chosen source measures and its scale.
- Why: owner ruling, 2026-10-12. Naming the scale in the label answers "how much thicker is twice as much" before the reader asks. Weights and edge counts sit in a narrow range where readers compare them directly; bytes and characters span orders of magnitude and would pin to the bounds on a linear scale. Old saved choices of Size or Attachments are dropped by the settings' option check, so those graphs draw Nothing.
- Pattern: none
- Status: ruling
