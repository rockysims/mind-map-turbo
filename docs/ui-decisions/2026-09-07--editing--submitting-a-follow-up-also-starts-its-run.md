# Submitting a follow-up also starts its run

- Situation: a composer commits a new object and moves the reader to it, and the object's whole purpose is to run something that costs money and takes seconds.
- Proposed: submit creates the node and focuses it, and the reader presses the node's own run control when they get there — one press per thing that happens.
- Chosen: submit creates the node, focuses it, and starts its first run. The reader has already written a request and pressed a verb; a second press on a node they did not choose to visit answers no question.
- Why: "yes, auto-run on submit" (owner's words)
- Pattern: status--name-the-pending-state-on-the-control — the press is only honest if the child's run control names what is in flight when focus lands on it. The mis-press cost is carried by the composer being a deliberate two-step, an empty prompt being unsubmittable, and Cancel sitting beside `Ask`.
- Status: ruling
