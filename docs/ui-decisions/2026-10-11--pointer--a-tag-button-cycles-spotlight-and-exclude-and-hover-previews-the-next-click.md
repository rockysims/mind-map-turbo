# A tag button cycles spotlight and exclude, and hover previews the next click

- Situation: the Find / Filter panel's node-tag and edge-tag buttons, each a toggle for its own query token. The earlier ruling (`2026-10-11--pointer--a-tag-button-cycles-its-token-and-hover-never-excludes.md`, now superseded) cycled none → `#tag` → `+#tag` → `-#tag` → none, and hover or keyboard focus previewed a spotlight only for a tag not in the query, never an exclusion.
- Proposed: keep the four-state cycle with plain focus as its first stop, and keep the hover preview from ever excluding, so nothing reflows under the pointer.
- Chosen: the cycle skips plain focus — none → `+#tag` (spotlight) → `-#tag` (exclude) → none. A hand-typed `#tag` still counts as in the query (pressed, "in focus") and its next click gives `+#tag`. Hover and keyboard focus preview exactly the query the next click would commit: `+#tag` for a tag not in the query, the exclusion for a spotlit tag (its nodes leave the layout while hovered), and the query without the tag for an excluded one (its nodes come back). Leaving restores the committed query the same way, and a click commits the previewed text unchanged, so the canvas does not move again on the click. Labels and accessible names are unchanged: the resting label is the bare `#tag`, the pressed ones `+#tag` / `-#tag`, and `aria-pressed` / `data-mode` separate a resting tag from a typed focus one. No debounce on the preview.
- Why: "show how it will look if clicked" (owner's words, relayed). The owner knows a previewed exclusion reflows the graph on hover and wants it; a debounce can be asked for later if hover flicker bites.
- Pattern: none — this reverses the earlier "a preview must not move what the pointer is over" reasoning for this control; the pointer is on the panel, not on the canvas that moves.
- Status: ruling
