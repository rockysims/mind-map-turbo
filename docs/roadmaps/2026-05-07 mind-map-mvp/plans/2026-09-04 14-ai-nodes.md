# Plan: AI nodes

**Created:** 2026-09-04
**Author:** Claude (Fable 5.1)
**Milestone:** [milestones/14-ai-nodes.md](../milestones/14-ai-nodes.md)
**Status:** draft
**Total estimated effort:** L

## Summary

Build the `!ai` add-on on milestone 13's registry and file attachments: a
one-screen key flow, a Messages API client that is a raw `fetch` behind an
interface, a Python executor that runs in a Web Worker, a typed run record,
proximity input collection with local digests, a workbench focus surface, the
run loop in which Claude calls the executor as a tool, and
promote-with-refresh. A half-day spike goes first and retires the unknowns
that remain after the 2026-09-04 review.

Agents: Opus subagents implement; Fable reviews T01's findings, the T03
request shape and system prompt, the T04 data model, the T06 worker protocol
and the T08 loop, re-runs the gates, and runs the end-to-end smoke test with
a real key and real CSVs.

## How hard is this, honestly

**Already paid for.** A generic blob asset store with export embedding and
tombstone-and-sweep GC (milestone 12). A single graph write path
(`commitUserGraph`) with undo labels. A full-screen focus surface per node
with nested image zoom. A pure title parser and, after milestone 13, an
add-on registry and file blocks. Directed edges. The persistence controller's
storage resolver, which the key store can reuse.

**Genuinely new.** Network I/O in an app that has none today (one `fetch` of
the offline shell is the whole current surface). A Python runtime loaded at
run time and driven from a worker. Long-running, cancellable, streamed work
with UI state that must not be persisted. A settings surface. Bindings from
one node's output to another node's content.

**What the review settled.** Anthropic's Files API refuses cross-origin
requests from every origin, and so do the models, token-count and batch
endpoints; only `/v1/messages` answers a browser page (verified with
preflights on 2026-09-04, including for the `null` origin a `file://` page
sends). So the code execution sandbox cannot receive inputs or return outputs
from this app without a relay, and the plan moved execution into the browser.
The SDK's browser build costs 188 KB minified regardless of how little is
imported, against a 599 KB shell, so the client is a raw `fetch`.

**Where the risk sits.** Two places: whether the Python runtime loads and
renders plots from a `file://` page inside a worker at an acceptable first-run
cost (T01 settles it in an afternoon), and the request shape that reliably
yields a script plus stable output filenames (T03, with the system prompt
below, iterated during the smoke test).

**Sizing.** Eleven tasks. Four carry design risk (T01, T03, T06, T08). The
cheapest useful subset is T01 through T08: a node that runs and shows
outputs, without promote or the two other modes.

## Open questions resolved

- **Key persistence.** **localStorage through the existing storage
  resolver, one entry for the whole app under its own prefix, with Forget key
  in the Model, cost and data section.** Convenience wins for a personal
  tool; the memory fallback covers browsers that block site data. Confirmed
  by the user 2026-09-04, with the three mitigations from the milestone's
  question 6 (a "Remember on this browser" choice, spending-limit advice,
  the CSP from T01) in place of a per-document wrapping key.
- **Runs kept.** **Three, as `ai.historyLength` in `APP_CONFIG`.** A guess
  that is cheap to change. Confirmed 2026-09-04.
- **AI node's own attachments as inputs.** **Yes.** The no-edge case should
  work. Confirmed 2026-09-04.
- **Default effort.** **`high` for analyse, `medium` for refine, fixed per
  mode in `APP_CONFIG.ai.effort` with no UI control; re-run calls no
  model.** T11 records tokens per run from the smoke test and moves these if
  needed; a three-stop Thoroughness control is the follow-up if they need to
  vary per user. Decided 2026-09-04.
- **Executor.** **Local: Pyodide in a Web Worker, loaded from a CDN, driven
  by Claude through one client-side tool.** Chosen by the user 2026-09-04
  after the review found the Files API unreachable from a browser; the
  alternatives were a small relay for the two Files endpoints (contradicts
  "nothing to deploy", passes the key through a third box) and inline-only
  data (toy sizes only).
- **Client.** **Raw `fetch` with a small SSE parser; `@anthropic-ai/sdk`
  stays a devDependency for `import type` only.** Decided 2026-09-04.
- **Default model.** **`claude-opus-5`, with `claude-sonnet-5` offered as
  the cheaper choice.** Re-run needs neither.
- **Runtime version and CDN.** **Pinned by T01.**

## Out of scope (for this plan)

- Everything in the milestone's Out of scope list.
- Undo for AI runs beyond what milestone 12 gives every commit.
- Image-as-node-background for promoted plots.
- Interrupting a running script without terminating the worker (needs
  shared memory, which `file://` pages cannot have).

### T01 — Spike: the runtime in a worker from a static page, and CORS from `file://`

| -------------- | --------------------------------------------------------------------------- |

A single static HTML page opened from `file://`. In a Web Worker: load Pyodide
from a CDN with a pinned version, load pandas, numpy, scipy and matplotlib,

the CDN and see whether the runtime still loads (it may need
`wasm-unsafe-eval`). Record: bytes downloaded and wall time for the first and
the cached runtime load, the runtime and package versions, the worker
protocol that worked, whether a CSV of 100,000 rows reads and plots in
reasonable time, the CORS result from `file://`, and the CSP outcome.

**Acceptance**

- A PNG rendered on the page from a script run in the worker.
- The notes section below filled in with the findings.
- A clear answer on `file://` CORS and on the CSP, each with the exact
  headers or tag used.

### T03 — Messages client behind an interface

|                |                                                                                                                                                                                              |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Depends on** | T01, T04                                                                                                                                                                                     |
| **Wave**       | 2                                                                                                                                                                                            |
| **Agent**      | opus (Fable reviews the request shape and system prompt)                                                                                                                                     |
| **Effort**     | L                                                                                                                                                                                            |
| **Files**      | new `src/lib/ai/aiClient.ts` (interface), `aiRequest.ts` + spec, `aiStream.ts` + spec, `anthropicClient.ts` + spec, `fakeClient.ts`, `package.json` (`@anthropic-ai/sdk` as a devDependency) |
| **PR title**   | `feat(ai): raw-fetch Messages client with pure request building and stream parsing`                                                                                                          |

`aiClient.ts` declares `AiClient { validateKey(key); send(request, { onEvent,
signal }): Promise<AiTurn> }`, where a turn is the assembled message: text,
thinking summaries, tool calls, stop reason, usage. `aiRequest.ts` is pure:
given the collected inputs with digests, the prompt, the mode, the previous
script and the settings, build the system prompt (Notes below), the
`run_analysis` tool definition (`strict: true`, one required string
argument), the first user message, and the follow-up messages that carry a
tool result (text plus image blocks for PNGs, capped in count and bytes by
`APP_CONFIG.ai`); it also sets `thinking: { type: 'adaptive', display:
'summarized' }`, `output_config.effort` per mode, a top-level `cache_control`
so the growing conversation is cached across loop iterations, and
`max_tokens` from config. `aiStream.ts` is pure: fold server-sent events
(`message_start`, `content_block_*`, `message_delta`, `message_stop`, and
`error`) into a turn, including `input_json_delta` for the tool call.
`anthropicClient.ts` does the `fetch` with the browser header, honours the
abort signal, maps HTTP errors to named states (invalid key, rate limit,
overloaded, other), and reads the body as a stream. `fakeClient.ts` replays
recorded turns for stories and specs. No `any`; message and block types come
from `@anthropic-ai/sdk` via `import type`.

**Acceptance**

- Request spec: analyse, refine (previous script with the edit instruction),
  labels from edge tags rendered into the prompt, digests rendered per file,
  a tool result with two PNGs becomes text plus two image blocks, a request
  built from a 10,000-row digest carries the configured preview rows only.
- Stream spec against recorded fixtures from T01: text and thinking
  summaries in order, one complete tool call with its parsed script,
  `refusal` and `max_tokens` classified, an `error` event surfaced.
- Client spec with a stubbed `fetch`: headers, abort mid-stream, 401 and
  429 mapped.
- `pnpm --filter mind-map-sv build` succeeds with no SDK runtime code in the
  shell (grep the shell for the SDK's package name).

`collectAiInputs(graph, nodeId)` returns, in a stable order, the node's own

### T06 — Python executor in a worker

|                |                                                                                                                                        |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Depends on** | T01                                                                                                                                    |
| **Wave**       | 2                                                                                                                                      |
| **Agent**      | opus (Fable reviews the worker protocol)                                                                                               |
| **Effort**     | L                                                                                                                                      |
| **Files**      | new `src/lib/ai/pyExecutor.ts` (interface + main-thread driver) + spec, new `src/lib/ai/pyWorker.ts`, new `src/lib/ai/fakeExecutor.ts` |
| **PR title**   | `feat(ai): run analysis scripts in a Pyodide web worker`                                                                               |

`PyExecutor { load(onProgress); digest(files, previewRows); run(script,
files, { timeoutMs, signal }): Promise<ExecutionResult>; dispose() }`, where
`ExecutionResult` is `{ exitCode; stdout; stderr; outputs: { name; mimeType;
bytes }[]; durationMs }`. `pyWorker.ts` loads the pinned runtime from the
configured `indexUrl` inside the worker (a runtime `import()` of the CDN
module, marked so Vite leaves it alone), loads the configured packages once,
writes the input blobs into the virtual filesystem under their attachment
names, runs the script with `matplotlib` forced to the Agg backend and a
clean `outputs/` directory, captures stdout and stderr, and posts back the
files it finds in `outputs/`. The driver owns the worker's lifetime: one
worker per page, created on first use, terminated on cancel or timeout and
recreated on the next run. Progress events carry bytes loaded for the runtime
line. The worker must ship inside the single-file shell (Vite's inline worker
import); check `inline-static-build.mjs` needs nothing for that, and extend
it if it does. `fakeExecutor.ts` returns scripted results for stories and
specs.

**Acceptance**

- Browser spec (client project): a script that writes a PNG and a CSV
  returns both with the right MIME types; a script that raises returns a
  non-zero exit code and the traceback in stderr; a script that loops is
  cut by the timeout and the executor is usable again afterwards.
- Spec: `digest` on a CSV returns columns, dtypes and the requested head.
- The offline shell still builds to a single file; its size delta is
  recorded in Notes.

|                |                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------- |

| **PR title**   | `feat(ai): run an ai node end to end from the focus surface`                                      |

Choose `AiNodeContent` in `focusDetails` when the node carries the add-on.
`aiRunController` owns in-flight state per node id (never persisted): ensure

executor and compute digests, then loop: `send`, and on a `run_analysis`

`refreshPromotedOutputs` through `commitUserGraph` with the label "run AI
node", and tombstone evicted assets through `assetTrash.ts`; on cancel abort
the request, dispose the executor, and record cancelled. `+page.svelte`
constructs the real client from settings and the real executor and passes
them down; stories pass the fakes.

**Acceptance**

- Controller spec with the fakes: success path with two tool calls commits
  one run, the right assets and the last completed script; cancel records
  cancelled and commits no outputs; a client error records error; the cap
  ends the loop with what ran; a missing key opens the sheet then continues.
- Smoke test with a real key: milestone acceptance criteria 1, 2, 5, 9.

## Risks and rollback

- **The runtime disappoints on `file://`.** T01 finds out first. If the
  worker cannot load it from a local page, the fallback is loading it on the
  main thread (with the page frozen during a run) and the plan notes it; if
  the CDN is the problem, a second pinned CDN is one config change.
- **First-run size.** Tens of megabytes is the expected cost; if T01
  measures far more, drop scipy from the default package set and load it on
  demand.
- **Output filenames drift between runs.** The system prompt asks for stable
  names and the refine instruction repeats it. If it still drifts, bind
  promoted nodes by position as a fallback and surface a rename control.
- **Runs cost more than expected.** The metadata line makes it visible from
  the first run; effort and model defaults are one config change, and a
  re-run costs nothing.
- **The key ends up somewhere it should not.** T02's grep gate and the
  export acceptance criterion guard it; both are cheap to keep forever.
- **The CORS policy changes.** The client has exactly one endpoint; if
  Anthropic ever refuses browsers there too, the relay in the milestone's
  out-of-scope list is the answer and the interface does not change.
